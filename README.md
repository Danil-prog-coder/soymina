# ИС управления задачами и формирования документов для Ярославского ИВЦ ОАО «РЖД»

Автономная информационная система для информационно-вычислительного центра (ИВЦ). Руководитель ставит задачи сотрудникам, исполнители ведут их до результата, а система по ходу работы формирует документы, оформленные по ГОСТ Р 7.0.97-2016.

Начиналось всё с темы «Формирование шаблонов документов для работы ИВЦ». Потом она расширилась до управления и распределения задач, и генерация документов стала одной из функций системы.

> Статус: проектирование. Процессы описываются в нотации IDEF0 (AllFusion Process Modeler r7). В коде есть схема базы данных (Tortoise ORM + PostgreSQL).

## Запуск для разработки

Нужны Python 3.12+ и Docker.

```bash
cp .env.example .env          # поменять пароль в POSTGRES_PASSWORD и в обоих URL
docker compose up -d --wait   # PostgreSQL 17; при первом старте создаётся и база ivc_test
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m tortoise migrate
.venv/Scripts/python -m pytest
```

Модели лежат в `app/models/`, миграции в `app/migrations/`. После изменения моделей выполните `python -m tortoise makemigrations`. В Tortoise 1.1.9 `CreateModel` не создаёт ограничения из `Meta.constraints`, поэтому для новых таблиц их нужно вынести в миграции в отдельные `ops.AddConstraint` (так сделано в `0001_initial.py`). Тесты используют только базу из `TEST_DATABASE_URL` с суффиксом `_test` и пересоздают её схему при каждом запуске.

## Роли

| Роль | Что делает |
|------|------------|
| **Начальник (руководитель)** | Создаёт задачу: описание, ответственный, срок, нужен ли документ и в каком формате, получатель. Принимает или отклоняет результат, может продлить срок. Закрыть задачу может только он. |
| **Исполнитель** | Принимает задачу, ведёт её на канбан-доске, выполняет и сдаёт результат. |

## Жизненный цикл задачи

```
Новая → Принята → В работе → На проверке → Завершена
                     ↑              │
                     └── отклонена ─┘
```

- Отклонённая задача возвращается в «В работе», дедлайн при этом продолжает идти.
- Просроченные задачи система помечает сама.
- При сдаче всегда ставится отметка «выполнено». Если по задаче нужен документ, без файла её сдать нельзя.
- Черновик документа генерируется автоматически, данные берутся из карточки задачи. Вместо черновика можно приложить документ, сделанный вручную.

## Нормативная база

- Федеральный закон № 152-ФЗ «О персональных данных»
- Федеральный закон № 149-ФЗ «Об информации, информационных технологиях и о защите информации»
- ГОСТ Р 7.0.97-2016 «Организационно-распорядительная документация. Требования к оформлению документов»
- Фирменный стиль ОАО «РЖД»

## Модель IDEF0

Правила, которых придерживаемся:

- **входы**: «что + от кого»;
- **выходы**: все возможные исходы (продукт, журнал, ошибка, отказ);
- **управления**: законы и стандарты;
- **механизмы**: пользователи и команда разработки.

### A-0. Контекстная диаграмма (утверждена, не меняется)

**Блок:** «Управление и распределение задач в ИВЦ».

| Тип стрелки | Стрелки |
|-------------|---------|
| Входы | Запрос руководителя; Решение исполнителя |
| Управления | 152-ФЗ; 149-ФЗ; ГОСТ Р 7.0.97-2016; Фирменный стиль ОАО «РЖД» |
| Выходы | Принятый результат задачи; Шаблон документа; Журнал документов; Сообщение об ошибке ввода; Отказ на выполнение запроса |
| Механизмы | Пользователь; Руководитель проекта ИВЦ; Программисты ИВЦ; Тестировщик ИВЦ |

### A0. Декомпозиция (готова, файл `BPwin_BD_v2.bp1`)

| Блок | Название |
|------|----------|
| A1 | Сформировать и назначить задачу |
| A2 | Принять задачу к исполнению |
| A3 | Выполнить задачу и подготовить решение |
| A4 | Проверить результат исполнения |
| A5 | Вести журнал задач и учёт исполнения |

**Внутренние связи:**

- A1 → A2: «Назначенная задача»
- A2 → A3: «Принятая задача»
- A3 → A4: «Решение на проверку»
- A4 → A5: «Итог проверки»

**Обратные связи:**

- «Отказ…» из A4 → вход A3 (подпись «На доработку»)
- «Новый срок исполнения» из A4 → управление A3

**Граничные стрелки:**

| Тип | Куда / откуда |
|-----|---------------|
| Входы | «Запрос руководителя» → A1; «Решение исполнителя» → A3 |
| Выходы | A3 → «Шаблон документа»; A1 и A3 (слияние) → «Сообщение об ошибке ввода»; A4 → «Принятый результат задачи», «Отказ на выполнение запроса»; A5 → «Журнал документов» |
| Управления | 152-ФЗ, 149-ФЗ → A1; ГОСТ Р 7.0.97-2016, Фирменный стиль → A3 |
| Механизмы | Пользователь → A1–A4; Руководитель проекта → A3; Программисты → A4, A5; Тестировщик → A5 |

### Следующий шаг

Декомпозиция A3 «Выполнить задачу и подготовить решение». В этот блок переходит прежняя логика формирования шаблонов документов.

## Заметки по AllFusion Process Modeler r7

- Если в подписях «крякозябры»: свойства блока → Font → Script «Кириллический» (Arial).
- Перенос строки в имени блока: Ctrl+Enter.
- Чтобы перенаправить граничную стрелку, нужно сделать ветку к нужному блоку, а старую ветку удалить.
- Блоки перетаскивать плавно: нажать кнопку мыши, сделать несколько движений, отпустить.
